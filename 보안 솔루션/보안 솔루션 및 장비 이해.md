### 인프라 기반 네트워크 보안 장비 구성

- BYOD(무선 인증)
    - 고성능 Wi-Fi 및 대역폭 확보 등 High-Density 환경을 지원하는 Wi-Fi 6 / Wi-Fi 6E 등 최신 무선 표준을 적용해야 함
    - 중앙 집중형 무선 제어 및 트래픽 분산
    - 네트워크 분리 (VLAN 및 SSID 구분)
- NAC
    - 미등록 기기나 보안 규정을 위반한 개인 기기의 사내 네트워크 차단
- MDM / MAM / UEM 솔루션 도입
    - MDM - 기기 전체를 원격 관리 및 모니터링
    - MAM - 개인 데이터는 건드리지 않고 업무용 앱과 데이터만 제어
    - UEM - PC·모바일·IoT 등 모든 엔드포인트를 하나의 콘솔에서 통합 관리
    - Containerization - 개인 영역과 업무 영역을 암호화된 공간으로 분리
- VMI (가상 모바일 인프라)
    - 민감한 데이터나 핵심 OS를 단말기가 아닌 서버(클라우드)에서 실행하여 기기 분실 시에도 정보 유출 위험을 제거
- WIPS (Wireless Intrusion Prevention System)
    - 사내 무선 네트워크 영역을 실시간으로 모니터링하여 보안 위협을 탐지 및 차단하는 보안 솔루션
    - Rogue AP 탐지 및 차단
    - Ad-hoc 네트워크 차단
    - 무선 해킹 공격 방어 및 위치 추적

### 방화벽과 이중화

**방화벽**은 신뢰할 수 없는 외부 네트워크와 신뢰할 수 있는 내부 네트워크 사이에서 무단 접근을 차단하고 허가된 트래픽만 통과시키는 보안 시스템이다.

**주요 기능**

- 접근 제어, 인증 및 암호화(VPN), 로그 및 감사
- 패킷 필터링 (Packet Filtering)
    - 패킷의 Source / Destination IP와 포트를 보고 단순 차단 / 허용 결정
- 상태 기반 검사 (Stateful Inspection)
    - 통신 세션의 연결 상태를 추적하여 정상적인 연결 흐름 안에 있는 패킷만 통과시킴
- 차세대 방화벽 (NGFW)
    - Application Control, 사용자 인식, IPS, 악성코드 분석 등 고도화된 보안 기능 결합

**이중화**는 시스템의 핵심 부품이나 장비(서버, 방화벽, 스위치 등)를 2개 이상으로 구성하여, 하나의 장비가 고장 나더라도 가용성을 보장하는 기술이다.

실무 환경에서는 보안과 안정성을 모두 챙겨야 하므로 **방화벽 자체를 이중화**하여 구성한다. 방화벽은 Single Point of Failure(단일 장애점)이기 때문에, 고장 나는 순간 기업 전체의 인터넷과 내부 네트워크가 마비되기 때문이다.

- **Active-Standby** : 한 대만 트래픽을 처리하고, 장애 시 대기 장비가 넘겨받음 (구성이 단순하고 안정적)
- **Active-Active** : 두 대가 동시에 트래픽을 분산 처리 (성능↑, 대신 세션 동기화 설계가 복잡)
- 두 장비는 Heartbeat 링크로 서로의 상태를 확인하고, 세션 정보를 동기화하여 Failover 시에도 연결이 끊기지 않게 한다.

#### Aggregation Setting

여러 링크를 묶어서 트래픽을 더 많이 감당하고, 링크 하나가 끊겨도 통신이 유지되도록 하기 위한 설정이다. 여기서 말하는 Aggregation은 다수의 물리 링크를 하나로 묶는 LACP / EtherChannel을 뜻한다.

- Northbound Aggregation : 방화벽에서 상위 라우터나 외부 인터넷 백본 스위치로 연결되는 링크들을 묶는 설정이다. 외부 공격을 막는 관문으로 대역폭을 넓히고 백업 링크를 확보한다.
- Southbound Aggregation : 방화벽에서 내부 핵심(Core) 스위치나 Workgroup 스위치로 연결되는 링크들을 묶는 설정이다.

> 💡 묶는 방식에 따른 기술적 방향
> 
> - **L2 Link Aggregation** : IP 주소 없이 단순히 대역폭 확장과 물리적 단선에 대비하여 스위치와 방화벽 포트를 묶는 방향
> - **L3 Link Aggregation** : 묶인 논리 인터페이스에 IP 주소를 할당하여 라우팅의 주체로 사용하는 방향

#### DMZ

**DMZ**는 네트워크 보안에서 외부 인터넷(위험 지역)과 내부망(안전 지역) 사이에 위치하는 중립적인 완충 구역이다. 실제 군사 접경지역의 DMZ 개념을 네트워크 보안에 그대로 가져온 것이다.

- 웹 서버, 메일 서버, DNS 서버처럼 **외부에 서비스를 제공해야 하는 서버**를 DMZ에 둔다.
- DMZ 서버가 해킹당하더라도 내부망까지 바로 뚫리지 않도록 막는 것이 목적이다.
- 기본 통신 정책
    - 외부 → DMZ : 서비스 포트(80, 443 등)만 허용
    - 외부 → 내부 : 차단
    - DMZ → 내부 : 원칙적으로 차단 (꼭 필요한 DB 연결 등만 예외 허용)
    - 내부 → DMZ : 관리 목적 접근(SSH 등)만 제한적으로 허용
- 구성 방식
    - 방화벽 1대에 인터페이스 3개(WAN / LAN / DMZ)를 두는 **3-Leg 구성**
    - 외부 방화벽과 내부 방화벽 사이에 DMZ를 두는 **Dual Firewall 구성** (보안성↑)

### N2SF (국가망보안체계)

- **N2SF (National Network Security Framework)** : 기존의 물리적 **망분리 정책의 한계를 보완**하기 위해 국가정보원이 마련한 공공기관 보안 체계
    - 2025년 1월 가이드라인 초안 공개, 2025년 9월 **가이드라인 1.0** 정식 발표
- 업무 정보를 등급별로 분류하고, 등급에 따라 다른 보안 통제를 적용한다.
    - **C (Classified, 기밀)** : 가장 높은 수준의 보호가 필요한 정보
    - **S (Sensitive, 민감)** : 내부 업무 정보 등 보호가 필요한 정보
    - **O (Open, 공개)** : 공개되어도 문제없는 정보 → 생성형 AI, 클라우드 등 외부 서비스 활용 가능
- 핵심 원칙
    - "망을 나누는 것"에서 "**정보를 등급으로 나누는 것**"으로 패러다임 전환
    - **제로트러스트** 원칙 적용 (누가, 어디서, 어떤 등급의 데이터에 접근하는지 지속 검증)
    - 높은 등급의 정보가 낮은 등급 구간으로 이동하는 지점을 위협 지점으로 보고 통제
- 담당 기관
    - 정책 수립 및 가이드라인 : **국가정보원**
    - 공공기관 도입 지원 사업 : **KISA** (한국인터넷진흥원)
- 공공기관 사이버보안 평가에서 기존 "망분리 시행 여부" 항목이 N2SF 적용 수준 평가로 바뀌는 추세

### WAF (Web Application Firewall)

일반적으로 네트워크 기반 웹 방화벽(Network-based WAF)과 호스트 기반 웹 방화벽(Host-based WAF) 형태로 구성된다.

- 웹 공격 방지
    - SQL Injection, Client-side 공격(XSS 등), 명령어 실행, 정보 유출 등의 공격에 대한 탐지 및 차단
- SSL 지원
    - 암호화된 HTTPS 트래픽을 복호화하여 내부 공격 페이로드까지 검사
- Positive Security Model 지원
    - 허용된 요청 형태만 통과시키고 나머지는 차단 (화이트리스트 방식)

**WAF 구성 방식**

- Network Based
    - Reverse Proxy : 클라이언트와 웹 서버 사이에서 요청을 대신 받아 검사 후 전달
    - In-line (Bridge) : 네트워크 경로 중간에 투명하게 설치
    - Monitoring : 트래픽을 미러링받아 탐지만 수행 (차단 불가)
- Host Based (Agent)
    - Linux - iptables / nftables
    - Apache Module (예: ModSecurity)

**탐지 방식**

- Signature 기반
    - 미리 정의된 공격 패턴을 탐지
    - 새로운 공격 기법을 반영하기 위해 주기적인 패턴 업데이트 필요
- Anomaly 기반
    - 정상적인 행위를 기준으로 학습하고, 비정상적인 행위 발생 시 탐지

### IDS / IPS

**IDS (Intrusion Detection System)** : 침입을 **탐지**하고 알리는 시스템 (차단은 하지 않음, 주로 미러링 방식으로 설치)

- 이상 징후 기반 IDS (Anomaly-based IDS)
    - 행위 기반 탐지 방식으로 정상 패턴과 비교해 벗어나는 행위를 탐지
- 시그니처 기반 IDS (Signature-based IDS)
    - 지정된 시그니처를 포함한 파일이나 패킷을 탐지

**IPS (Intrusion Prevention System)** : 침입을 탐지하고 **실시간으로 차단**하는 시스템 (In-line 방식으로 설치)

- 탐지 방식
    - 시그니처 기반 탐지 (Signature-based Detection) : 미리 구성된 패턴과 비교하여 차단
    - 통계적 이상 징후 기반 탐지 (Statistical Anomaly-based Detection) : 평소 트래픽 기준치와 비교하여 차단
- 종류
    - NIPS : 전체 네트워크상 의심스러운 트래픽 식별
    - WIPS : 무선 네트워크 프로토콜 식별
    - NBA (Network Behavior Analysis) : DDoS 공격 등 비정상 트래픽 위협 식별
    - HIPS : 호스트에서 발생하는 이벤트를 분석 및 식별

|구분|IDS|IPS|
|---|---|---|
|역할|탐지 + 알림|탐지 + 차단|
|설치 위치|Out-of-band (미러링)|In-line (경로 중간)|
|장애 영향|장애 나도 통신 영향 없음|장애 시 통신 단절 가능|
|오탐 영향|알림만 발생|정상 트래픽 차단 위험|

### Anti-DDoS

- DDoS 공격을 방어하기 위한 네트워크 보안 장비
- ISP 업체는 기본적인 DDoS 방어를 위해 Backbone 네트워크 하단에 위치시킴
- 주요 기능
    - 대량 트래픽(Volumetric) 공격 완화 : UDP Flood, ICMP Flood 등
    - 프로토콜 공격 방어 : SYN Flood 등 (SYN Cookie, 세션 검증)
    - 애플리케이션 계층 공격 방어 : HTTP GET Flood, Slowloris 등
- 일정 규모 이상의 공격은 장비만으로 감당이 어려워, ISP나 클라우드 기반 **스크러빙 센터**와 함께 사용

---

### DLP (Data Loss Prevention)

- 기업 내부의 **중요 정보(개인정보, 기밀문서 등)가 외부로 유출되는 것을 탐지·차단**하는 솔루션
- 적용 영역
    - Network DLP : 이메일, 웹 업로드, 메신저 등 네트워크로 나가는 데이터 검사
    - Endpoint DLP : USB, 프린터, 클라우드 동기화 등 PC에서 나가는 데이터 통제
    - Storage DLP : 파일 서버나 DB에 저장된 민감 정보 검색 및 관리
- 탐지 방식 : 주민등록번호·카드번호 같은 패턴(정규식), 키워드, 문서 핑거프린팅 등

---

### DRM (Digital Rights Management)

- 문서 자체를 **암호화**하고, 권한이 있는 사용자만 열람·편집·출력할 수 있도록 통제하는 솔루션
- 파일이 외부로 유출되더라도 암호화되어 있어 내용을 볼 수 없음
- DLP와의 차이
    - DLP : 데이터가 **나가는 것 자체를 막음** (유출 경로 통제)
    - DRM : 나가더라도 **열어볼 수 없게 함** (파일 자체 보호)

---

### SIEM (Security Information and Event Management)

- 방화벽, IPS, 서버, 애플리케이션 등 **다양한 장비의 로그를 한곳에 수집**하고, 이를 **상관 분석(Correlation)** 하여 위협을 탐지하는 솔루션
- 기능
    - 로그 수집 및 정규화, 장기 보관
    - 여러 장비의 이벤트를 연결해 하나의 공격 시나리오로 탐지
    - 대시보드, 실시간 알림, 컴플라이언스 리포트
- 예시 : Splunk, IBM QRadar, Elastic Security 등

---

### ESM (Enterprise Security Management)

- 여러 보안 장비(방화벽, IDS/IPS, 백신 등)를 **통합 관리·모니터링**하는 솔루션
- SIEM의 전 세대 개념
    - ESM : 주로 **보안 장비 이벤트** 중심의 통합 관제
    - SIEM : 보안 장비 + 서버·애플리케이션 등 **전체 로그**를 빅데이터 기반으로 분석

---

### EDR (Endpoint Detection and Response)

- PC, 서버 등 **엔드포인트에서 발생하는 행위를 지속적으로 기록·분석**하여 위협을 탐지하고 대응하는 솔루션
- 기존 백신(시그니처 기반)이 놓치는 **파일리스 공격, 알려지지 않은 악성코드** 등을 행위 기반으로 탐지
- 기능
    - 프로세스 실행, 파일 변경, 네트워크 연결 등 행위 기록
    - 위협 탐지 시 단말 격리, 프로세스 종료 등 원격 대응
    - 침해 사고 발생 시 공격 경로 추적(포렌식)
- 확장 개념 : XDR (엔드포인트 + 네트워크 + 클라우드 등을 통합 탐지·대응)

---

### SOAR (Security Orchestration, Automation and Response)

- 보안 관제 업무를 **자동화**하여 대응 속도를 높이는 솔루션
- 구성 요소
    - Orchestration : 여러 보안 솔루션을 연동
    - Automation : 반복적인 대응 작업을 **플레이북(Playbook)** 으로 자동 처리
    - Response : 사고 대응 프로세스 관리 (티켓, 이력 관리)
- 예시 : SIEM에서 악성 IP 탐지 → SOAR가 자동으로 평판 조회 → 방화벽에 차단 룰 등록 → 담당자에게 알림

> 💡 흐름으로 보면 : **수집·탐지(SIEM)** → **대응 자동화(SOAR)** → **단말 대응(EDR)**

---

### WIPS (Wireless Intrusion Prevention System)

- 무선 네트워크 환경에서 비인가 AP, 무선 공격 등을 탐지·차단하는 시스템
- 상세 내용은 상단 [인프라 기반 네트워크 보안 장비 구성] 의 WIPS 항목 참고
- 주요 탐지 대상
    - Rogue AP (비인가 AP), Evil Twin (정상 AP를 위장한 가짜 AP)
    - Ad-hoc 연결, 비인가 단말 접속
    - Deauthentication 공격 등 무선 해킹 시도

### 참고 사례 : BPFDoor

- 리눅스 서버에 숨어드는 **백도어 악성코드**로, 리눅스 커널의 **BPF(Berkeley Packet Filter)** 기능을 악용
- 특징
    - 평소에는 포트를 열지 않고 숨어 있다가, 공격자가 보낸 **특정 "매직 패킷"** 을 받으면 활성화됨
    - 방화벽보다 앞단(커널 레벨)에서 패킷을 가로채기 때문에 **방화벽 정책을 우회**할 수 있음
    - 포트가 열려 있지 않아 일반적인 포트 스캔으로 탐지가 어려움
- 시사점 : 방화벽만으로는 충분하지 않으며, EDR·서버 무결성 점검·이상 프로세스 모니터링 등 **다층 방어**가 필요함
