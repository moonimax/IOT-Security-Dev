
## 1. 침해 지표 — IOC vs IOA

침해사고 탐지는 크게 두 관점으로 나뉜다. "이미 남은 흔적"을 보는 IOC와, "지금 하는 행동"을 보는 IOA다.

### IOC (Indicator of Compromise, 침해 지표)
- 특정 침해사고의 **증거 및 흔적**을 의미하는 데이터.
- 공격에 활용된 인프라: 악성 IP/도메인, 파일 해시값, 악성 파일명/경로 등.
- 성격: "이미 당한 흔적" → **사후(reactive) 탐지**에 쓰인다.
- 한계: 공격자가 해시·IP·도메인만 바꿔도 우회된다(쉽게 변한다).

### IOA (Indicator of Attack, 공격 지표)
- 공격자의 **행동(행위)에 초점**을 맞춘 데이터.
- 아직 피해가 없어도 "공격자가 지금 무엇을 하려는지" 그 **패턴/의도**에 집중.
- 성격: "공격 중인 행동" → **실시간(proactive) 탐지**에 쓰인다.
- 장점: 도구(해시/IP)가 바뀌어도 **행위 패턴은 잘 안 변하므로** 탐지 지속성이 높다.

## 2. 공격 시나리오 ↔ MITRE ATT&CK 매핑

> MITRE ATT&CK은 실제 공격자의 행위를 전술(Tactic, 왜) / 기법(Technique, 어떻게)으로 분류한 표준 지식체계다. 사고 분석 시 각 행위를 ATT&CK ID로 매핑하면 보고서 표준화와 방어 커버리지 점검이 쉬워진다.

### 1) 웹 서비스 취약점 기반 파일 업로드 공격으로 웹쉘 업로드
- 전술(Tactic): `TA0001` — Initial Access (초기 침투)
- 기법(Technique): `T1190` — Exploit Public-Facing Application (공개 서비스 취약점 악용)


### 2) 웹쉘을 통해 지속적으로 시스템 내부에 접근
- 전술: `TA0003` — Persistence (지속성)
- 세부 행위:
  1. 웹쉘을 통해 시스템 내부에 직접 진입하기 위한 **리버스 커넥션 명령어** 수행
     - `T1059` — Command and Scripting Interpreter (명령/스크립트 인터프리터)
  2. **작업 스케줄러(cron/at)**를 이용해 매일 자정에 `malware.exe` 실행
     - `T1053` — Scheduled Task/Job (예약 작업)

## 3. 실습 — 흔적 찾아보기


### 최근 접속한 웹사이트 DNS 찾아보기

![](../Images/Pasted%20image%2020261117154428.png)

> DNS 캐시(`ipconfig /displaydns`)나 브라우저 기록은 **C2/악성 도메인 접속 흔적**을 남긴다. 접속 시각과 도메인을 타임라인에 연결하면 초기 침투 경로 추정에 도움이 된다.



### 이벤트 뷰어에서 특이사항 확인
감염 시점을 찾기 위해, 악성코드가 실행되기 이전의 **응용 프로그램 / Windows 로그**를 확인한다.

![](../Images/Pasted%20image%2020261117154650.png)



여기서는 **MAC time을 얻지 못했다.**

> MAC time = Modified / Accessed / Changed 시각. 파일이 언제 생성·수정·접근됐는지 추적하는 핵심 타임스탬프. MAC time이 소실·변조된 경우에는 **USN 저널, Prefetch, 이벤트 로그** 등 다른 아티팩트로 타임라인을 교차 검증해야 한다.

## 4. 정리

- **IOC**로 "이미 남은 흔적"을 빠르게 매칭하고, **IOA**로 "진행 중인 행위"를 탐지하는 **이중 접근**이 효과적이다.
- 수집한 각 행위를 **MITRE ATT&CK에 매핑**하면 공격 체인을 표준 언어로 기술할 수 있고, 어느 단계에서 탐지/차단이 비었는지 한눈에 보인다.
- 타임라인 재구성이 분석의 핵심이며, MAC time이 믿을 수 없을 때는 **시스템이 자동 생성하는 아티팩트(USN, Prefetch 등)**로 보완한다.
