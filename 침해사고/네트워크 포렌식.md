# 패킷 분석 실습

시스템에서 활용한 네트워크 증거를 수집·분석한다. Wireshark로 pcap을 분석해 공격 유형, 공격자/피해자, 성공 여부를 판별한다.

> 참고: 네트워크 포렌식은 디스크만으로 알 수 없는 통신 흐름(누가 누구와 무엇을)을 복원한다. 단일 PC 디스크로는 사건 흐름을 못 보므로, 패킷·보안장비 로그를 함께 보는 **상관분석**이 필요하다.

## 실습 1 — ARP Spoofing (MITM)

![](../Images/Pasted%20image%2020261124151331.png)

ARP 스푸핑을 이용한 **MITM**이다.

### ARP Spoofing 원리
- ARP는 **IP ↔ MAC 주소**를 매핑하는 프로토콜인데, 인증이 없다.
- 공격자가 "게이트웨이의 MAC은 내 MAC이다"라는 위조 ARP 응답을 피해자에게 보내면, 피해자의 ARP 캐시가 오염되어 트래픽이 공격자를 경유하게 된다.
- 결과적으로 공격자가 피해자-게이트웨이 사이에 끼어 **도청/변조** 가능.

### 탐지 단서
- 하나의 IP에 서로 다른 MAC이 매핑되거나, 동일 MAC이 여러 IP를 주장하는 ARP 응답 폭주.
- Wireshark 경고: "duplicate use of IP address detected".

## 실습 2 — FTP 사전 대입 공격 (Dictionary Attack)

![](../Images/Pasted%20image%2020261124153704.png)

![](../Images/Pasted%20image%2020261124154050.png)

| 질문               | 답                               |
| ---------------- | ------------------------------- |
| 타겟 서비스 프로토콜 / 포트 | **FTP / 21**                    |
| 공격 이름            | **사전 대입 공격(Dictionary Attack)** |
| 집중 공략 계정 2가지     | **admin, administrator**        |
| 성공 여부 확인 필터      | `ftp.response.code == 230`      |

### Brute Force vs Dictionary
- **무차별 대입(Brute Force):** 가능한 **모든 조합**을 순차 시도.
- **사전 대입(Dictionary):** `merlin`, `mike`처럼 의미 있는 단어 목록(사전)을 대입. 
나는 브루트 포스라고 생각했지만 여기서는 무작위 조합이 아니라 리스트된 단어를 썼으므로 **Dictionary**가 정답.

### 성공 판별
- FTP 응답코드 **`230` = 로그인 성공**(User logged in). `530` = 로그인 실패.
- 필터 `ftp.response.code == 230`에 결과가 없으면 **로그인 실패(공격 미성공)**로 판단.

## 실습 3 — 비정상 트래픽 (SYN Flooding / Port Scan)

![](../Images/Pasted%20image%2020261124161527.png)

| 질문           | 답                                              |
| ------------ | ---------------------------------------------- |
| 프로토콜 / 공격 종류 | **TCP / SYN을 이용한 Port Scan (또는 SYN Flooding)** |
| 열린 포트        | **139**                                        |
| 포트 서비스       | NetBIOS Session Service                        |
| 공격 대상 IP     | 157.157.116.14                                 |

### SYN Flooding vs Port Scan (핵심 구분)
- 둘 다 SYN 패킷을 대량 전송해 겉보기가 비슷하다.
- **SYN Flooding (DoS):** 핸드셰이크를 고의로 미완성**(ACK 안 보냄)으로 두어 서버의 연결 대기 큐(Backlog)를 고갈시킨다. → 목적은 부하.
- **Port Scan (정찰):** 어떤 포트가 열려 있는지 탐지가 목적. 부하를 주려는 게 아니다.
- 판별 기준: 요청 대비 서버가 닫히거나 영향을 받으면 DDoS/DoS**, 요청해도 영향이 없고 응답만 받으면 Port Scan에 가깝다.

### Half-Open Scan (SYN Scan)
- 공격자가 `SYN → (서버)SYN/ACK → (공격자)RST`로 연결을 완성하지 않고 강제로 끊는다.
- 3-way 핸드셰이크를 끝내지 않아 로그에 연결 기록이 잘 안 남아 은밀하다. 그래서 "Half-Open(반열림) 스캔"이라 부른다.
- 포트 상태 판별: `SYN/ACK` 수신 = **열림**, `RST` 수신 = **닫힘**.

> 포트 139(NetBIOS)는 Windows 파일공유 관련 포트로, 과거 웜·측면이동의 단골 대상이다.

## 실습 4 — CGI Attack


- **CGI(Common Gateway Interface):** 웹서버가 동적 페이지를 처리하려고 외부 프로그램(Bash, Perl, C, Python 등)을 OS 레벨에서 직접 실행하는 구조.
- 이 구조를 악용하면 OS 명령어 인젝션, 환경변수 조작, RCE로 이어진다.
- CGI 스캐닝으로 취약 스크립트 존재 여부를 탐지.
- 성공/실패 판별: 응답 **status 200**을 검색하되, `naver.com` 같은 정상 URL을 제외하고 보면 공격 성공 요청을 가려낼 수 있다.
