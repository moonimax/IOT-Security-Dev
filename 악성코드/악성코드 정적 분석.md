# 악성코드 정적 분석 (Static Analysis)

의심 파일은 **인터넷 차단된 분석 전용 VM**에서만 열고, 실행(동적 분석)은 스냅샷 복구가 가능한 샌드박스에서만. 아래는 **실행하지 않고** 파일을 뜯어보는 정적 분석 기록.

---

## 0. 정적 분석이란? (vs 동적 분석)

| 구분 | 정적 분석 (Static) | 동적 분석 (Dynamic) |
|---|---|---|
| 정의 | **실행하지 않고** 파일 구조·코드·문자열을 분석 | **실제 실행**시켜 행위(네트워크·레지스트리·프로세스)를 관찰 |
| 장점 | 안전, 전체 구조 파악, 빠름 | 실제 동작·C2 주소 등 확인 |
| 한계 | **패킹/난독화**되면 내부가 안 보임 | 환경 탐지 회피(anti-VM) 시 안 돎 |

정적 분석의 목표: **"이 파일이 무엇이고, 수상한 구석은 어디인가"**를 실행 없이 판별하고 **IOC(침해지표)**를 뽑는 것.

## 1. 1차 관찰 — 파일 속성부터 의심

![](../Images/Pasted%20image%2020261120151405.png)

![](../Images/Pasted%20image%2020261120151440.png)

파일 속성만 봐도 여러 정황이 의심스러워지기 시작한다.

VM 환경에서 **Detect It Easy(DIE) 2.0**과 **PEStudio 8.88**을 준비해 분석한다.

> 📖 **분석 도구 소개**
> - **DIE (Detect It Easy):** 파일의 **컴파일러·패커·프로텍터**를 시그니처로 식별하고, **엔트로피 그래프**로 난독화 여부를 보여주는 도구.
> - **PEStudio:** PE 파일을 실행 없이 열어 **헤더·임포트(API)·문자열·리소스**를 보여주고, **위험 지표(blacklist)**를 빨간색으로 하이라이트해주는 트리아지 도구.

![](../Images/Pasted%20image%2020261120151558.png)

![](../Images/Pasted%20image%2020261120151611.png)

문제의 `518...` 파일은 전반적으로 수상하다:
- 설명(Description)이 **간체자**로 `클라이언트 복구 도구`라고 적혀 있음 (제작 출처 의심)
- 파일 형식/용도가 모호함
- **생성 날짜 ≒ 수정 날짜**로 거의 붙어 있어, **타임스탬프 위조(timestomping)** 가능성

## 2. DIE — 컴파일러/링커 식별

![](../Images/Pasted%20image%2020261120152647.png)

**DIE 결과 해석:**
- **MASM32 Compiler 식별**
    - 32비트 Windows에서 **Microsoft Macro Assembler(MASM)**로 **어셈블리 코드를 직접 작성·빌드**한 SDK. → 고급언어(C/C++)가 아니라 **어셈블리로 짰다**는 건, 작고 은밀하게 만들려는 **의도된 저수준 제작**일 수 있음 (악성코드에서 흔한 신호).
- **Microsoft Linker `Segmented-Executable Linker Version 5.20`**
    - 1990년대 초 **MS-DOS / Windows 3.x / OS/2용 16비트 실행파일**을 만들던 **고전 링커(LINK.EXE) 버전**.
    - 🚩 **왜 수상한가:** 현대 Windows 실행파일(PE32)인데 **링커 버전은 90년대 초 것**으로 찍혀 있음 → **헤더 정보 위조 / 안티 분석**의 전형. 분석가·자동 도구를 혼란시키려는 흔적.

![](../Images/Pasted%20image%2020261120152934.png)

**PIE / 심층 보기** — 파일을 더 깊이 파고들어 구조를 뜯어보는 도구.

![](../Images/Pasted%20image%2020261120153053.png)

**first-bytes-hex** — 파일 선두 바이트(매직 시그니처)로 **파일 종류의 기본 정보**를 보여준다.

> 📖 **매직 시그니처 상식:** Windows 실행파일은 **`4D 5A`(="MZ")**로 시작(DOS 헤더)하고, 내부에 **`50 45`(="PE")** 시그니처가 있어야 정상 PE다. 시그니처와 확장자가 안 맞으면 위장 의심.

![](../Images/Pasted%20image%2020261120153320.png)

## 3. 엔트로피 — 난독화/패킹 판별

![](../Images/Pasted%20image%2020261120153417.png)

**Entropy(엔트로피)**는 데이터의 **무질서도(0~8)**를 수치화한 것으로, **난독화·암호화·패킹 정도**를 가늠하는 지표다. 이 파일은 **약 7.7**로 측정된다.

| 엔트로피 | 의미 |
|---|---|
| **0 ~ 3** | 난독화 거의 없음 (평문/일반 데이터) |
| **4 ~ 6** | 보통 수준 (일반적인 코드·리소스) |
| **7 ~ 8** | **패킹/암호화/난독화 강함** — 압축되거나 숨겨진 코드일 가능성 높음 |

➡️ **7.7**이면 사실상 **거의 완전 난독화/패킹** 상태 → 내부 코드가 숨겨져 있어 **언패킹 후 재분석**이 필요하다는 신호. (정상 프로그램도 압축 설치파일은 높게 나올 수 있으나, 위 정황들과 겹치면 악성 가능성 ↑)

## 4. PEStudio — 위험 지표 하이라이트

![](../Images/Pasted%20image%2020261120154126.png)

PEStudio는 위험하다고 판단되는 항목을 **빨간색**으로 표시해준다. (의심 API 임포트, 알려진 악성 문자열, 비정상 섹션명 등)

> 📖 **정적 분석에서 특히 봐야 할 "의심 API" 예시:** `VirtualAlloc`/`WriteProcessMemory`/`CreateRemoteThread`(코드 인젝션), `URLDownloadToFile`/`WinHttp*`(다운로더), `RegSetValue`(자동실행 등록), `CryptEncrypt`(랜섬웨어 의심), `IsDebuggerPresent`(안티디버깅).

## 5. 정리 — 이 파일을 "악성 의심"으로 보는 근거

이번 정적 분석에서 쌓인 **IOC/의심 정황**:

1. 설명이 **간체자**로 `클라이언트 복구 도구` (출처·용도 불명)
2. **생성≈수정 날짜** → 타임스탬프 위조 정황
3. **MASM 어셈블리**로 제작 (저수준·은닉 의도 가능)
4. **90년대 16비트용 고전 링커 버전** 표기 → 헤더 위조/안티분석
5. **엔트로피 7.7** → 강한 패킹/난독화
6. PEStudio **다수 빨간 지표**



> **결론:** 한두 개면 우연일 수 있으나 **여섯 개가 겹치면 "악성 고의심"**으로 분류한다. 다음 단계는 ① **언패킹 → 재정적분석**, ② **격리 샌드박스에서 동적 분석**(네트워크·레지스트리·프로세스 관찰)으로 C2·행위를 확인하는 것.
